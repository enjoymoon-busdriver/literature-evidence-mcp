## 一、先选你需要的功能

MCP 可以理解为“让 AI 读取文献库的接口”；Tunnel 是“让 ChatGPT 网页连回这台电脑的通道”；向量是帮助按语义找资料的数据，不是文档本身。

| 你要做什么 | 需要设置什么 | FolioHook 是否调用付费模型 |
|---|---|---|
| 在应用里整理文档、普通搜索 | 启动应用、建库、导入 | 否，无需 API Key |
| 让本机 Codex 普通检索 | 上一项 + 本机 MCP 配置 | 检索本身不调用模型；客户端自身的用量另算 |
| 在应用或本机 MCP 中增强检索 | 阿里云 Key、三个模型角色、目标版本向量 | 是，按明确操作发送 |
| 让 ChatGPT 网页普通检索 | OpenAI Tunnel、运行 Key、网页连接 | 不调用阿里云模型；ChatGPT／服务端计费规则另算 |
| 让 ChatGPT 网页增强检索 | 网页连接 + 阿里云设置 + 目标版本向量 | 是 |

两个 Key 不要混填：

- **阿里云 Key**：填在「全局设置」，用于搜索词优化、向量和排序，三个角色共用这一份。
- **OpenAI Tunnel 运行 Key**：填在「连接 AI 应用」的真实 Tunnel 区，用来运行网页连接，不是本项目三模型搜索的 Key。

只做本地普通搜索，可以两份 Key 都不填。Key 由你自己生成、输入并保存到本机钥匙串；不要发到聊天、截图、Git 仓库或配置示例中。

## 二、安装与启动

### 2.1 首次使用的条件

当前开发入口面向 Apple Silicon Mac（M 系列）：

- 保留完整、来源可信的项目目录，不能只拿走 `.command` 文件。
- 需要 Python 3.11 或更新版本；其 SQLite 必须支持实际可用的 FTS5 和 `serialize/deserialize`。启动器会检查，不需要你理解这些术语。
- 首次安装依赖需要网络；普通运行不要求安装 Node、Docker 或虚拟机。
- 没有合适 Python 时，按启动器提示从 [Python.org macOS 下载页](https://www.python.org/downloads/macos/) 安装，再试一次。不要为通过检查关闭系统安全功能。

若电脑上已有 FolioHook，先确认现有版本和资料位置，再启动另一个源码目录：**复制项目或建立 Git 工作树，不等于复制出独立文献库**。默认入口可能共用资料、钥匙串和本机 MCP 启动入口。

### 2.2 正常启动

1. 在 Finder 打开维护者确认的完整项目目录。
2. 双击「启动文献证据管理页.command」。系统拦截时先看提示；未签名开发脚本可尝试 Finder 右键「打开」，不要关闭 Gatekeeper。
3. 等环境检查和首次依赖安装完成。后续源码未变、环境完整时，不会每次重装。
4. 以终端实际显示的地址为准打开管理页；默认是 `http://127.0.0.1:8765/`。
5. 保持启动它的终端窗口打开。

**成功标志：** 管理页能加载，能看到文献库与侧边栏。只有终端窗口打开、或浏览器显示旧页面，不足以证明服务仍在运行。

如果需要 Agent 先检查环境，可让它在确认的项目目录运行：

```bash
/bin/zsh ./启动文献证据管理页.command --preflight-only
```

这一步只预检，不安装、不启动服务。正式准备和启动应继续使用项目原入口，不另写安装器。

### 2.3 单独试用，不碰正式资料

已有正式库时，建议由维护者用开发版的 `--test-instance` 参数准备独立测试实例；另用一个未占用端口。例如在**已包含隔离入口功能**的项目目录执行：

```bash
/bin/zsh ./启动文献证据管理页.command --test-instance tutorial --port 18769
```

`tutorial` 是示例名，`18769` 是示例端口，不是正在运行服务的保证。先确认同名实例是否已存在，不能把旧实例当空库。

测试实例的环境和资料位于该项目的 `local-artifacts/test-instances/tutorial/`，MCP 配置和钥匙串作用域也与默认实例区分。只用合成资料；需要测试云服务时使用专用测试 Key，不复制生产 Key。页面「勿误填正式 Key」提示不代表所有真实服务都不可用，而是提醒你不要误用生产凭据。

## 三、建库、导入与版本管理

### 3.1 建库

1. 左侧点「＋ 新建」。
2. 填一个便于区分的库名，例如「AI 阅读练习」；简介写明用途。
3. 点「创建文献库」。
4. 确认左侧选中的库、页面标题与预期一致，再导入。

不同主题可以分库。库名可修改，不必用很长的文件路径当名称；同名库也可能存在，删除或连接测试时仍要核对库身份。

### 3.2 导入文件

1. 点「＋ 导入文档」。
2. 选择建立方式：
   - **基于当前浏览版本继续**：保留该版本的文档，再加入本次选择的文件。
   - **从空白建立**：新版本只包含本次文件，不继承旧文档；旧版本不会因此删除。
3. 拖入或选择 UTF-8 Markdown、带文本层 PDF。扫描图片型 PDF 不能当作已支持 OCR 的文件处理。
4. 核对目标库、基础版本、文件名单，然后点「明确导入并建立版本」。
5. 等待结果，检查逐文件状态与新版本中的文档数；有失败项先看错误，不把选中文件当成导入成功。

**成功标志：**「版本历史」出现新版本，浏览该版本能看到预期文档。

### 3.3 三个版本状态不要混淆

| 页面用语 | 含义 | 什么时候变化 |
|---|---|---|
| 正在浏览 | 你现在查看、搜索的版本，也是“继续导入”的基础 | 点「浏览文档」或切换浏览对象 |
| 当前版本／当前激活 | 对外使用时通常希望 AI 选择的版本 | 首次成功建立，或你点「设为当前版本」 |
| 上次成功 | 最近一次成功建立的版本 | 新版本建立成功 |

首次成功版本会自动成为当前版本；以后导入或移除文档建立的新版本，**不会自动替换当前版本**。确认新版本合适后，到「版本历史」点「设为当前版本」。

AI 接口每次仍须明确指定库与版本，不会凭页面正在浏览的内容自动选库。提问时可以说“使用这个库的当前激活版本”。

短版本名便于阅读；排查问题或精确复现时展开「版本详情」→「复制完整 ID」。

「检查版本完整性」检查保存内容与索引等是否符合该版本记录，**不是检查文献观点正确，也不是重新生成向量**。

## 四、搜索与核对出处

### 4.1 先用普通搜索

1. 选库，再确认页面顶部的浏览版本。
2. 左侧进「搜索」，选择本地 BM25（关键词搜索）。
3. 输入原文中确实出现的词，再提交。
4. 查看摘录、文件名、PDF 页码或 Markdown 行号。

BM25 在本机执行，不需要 Key 或向量。中文连续词的匹配有局限；没结果时可尝试原文中的较明确词语，不要把空结果理解为库里绝对没有相关内容。

切换 BM25／AI 增强搜索会保留输入、清除旧结果，**不会自动搜索**；需要再次提交。

### 4.2 详情与选中样式

- 点文档或搜索结果可以查看详情、来源和导航；右键文档可选「查看详情」。
- 搜索结果默认预览不表示你已选中；鼠标悬停与点击选中的样式不同，选中应只对应一个结果片段。
- 「文本片段：N 段」是文档被拆分后的段数，不是页数，也不直接等于已调用 N 次模型。

### 4.3 核对原文

1. 先记下结果的文件名和页码／行号。
2. 在详情的「文档导航」查看对应提取段落。
3. 再用系统阅读器打开你保存的原始 PDF，按 PDF 页序核对；Markdown 则用文本编辑器核对标题与行号。印刷页码可能与 PDF 页序不同。

当前详情是提取文本导航，**不要假定点击它就会自动打开原 PDF 或完成逐字核验**。尤其公式、表格和扫描材料，不能只看 AI 摘录就认为提取正确。

## 五、配置三个模型与准备向量

### 5.1 最简单的模型设置

只在你决定使用付费增强搜索时进行：

1. 进入「全局设置」。当前接入是「阿里云百炼 · 北京（cn-beijing）」。
2. 你自行准备该地域、具有相应模型调用权限的专用 API Key，填入「阿里云 API Key」。
3. 点「保存到本机钥匙串」，确认显示已配置。保存本身不调用模型，也不证明 Key 有效。
4. 点「使用推荐配置」，采用当前应用提供的三个角色型号；已有 Key 与启用状态保留。
5. 勾选「启用 AI 增强搜索」。这允许增强，不会自动开始检索。

当前开发版本内置值如下，是版本记录，不保证供应商永久提供这些型号：

| 角色 | 用途 | 当前内置型号 |
|---|---|---|
| 搜索词优化 | 把问题整理成检索用语 | `qwen3.8-flash` |
| 向量模型 | 把问题和文档片段转换为可比较的语义数据 | `qwen3.7-text-embedding` |
| 排序模型 | 对召回的候选片段重新排序 | `qwen3-rerank` |

初用不必展开「高级设置 · 三个模型角色」。确实要更换时，核对服务商可用型号与应用支持范围，修改后点「保存模型设置」；不要把聊天模型填入向量模型一栏。

「检查三个模型连接」是**可选的真实请求**：三个角色各做少量测试，可能产生费用，失败不自动重试。它不是免费的本地状态查看，也不替代准备文献向量。

### 5.2 准备目标版本的向量

1. 进入「版本历史」，找到准备使用的版本。
2. 点该版本「准备向量」。
3. 点「查看发送量」，核对新增片段、字符数、计划调用次数与复用量。这一步只预览，不发送模型请求。
4. 确认允许这些文本发送给模型服务商并接受费用后，点「明确发送并构建向量」。
5. 等结果成功，再查看该版本的向量状态。

不能只看每篇文档都有「已向量化」就跳过版本状态：文档对象可复用，不等于新版本所需的完整向量映射已经准备好。

文档标识：

- **已向量化**：当前配置下存在可用向量。
- **未向量化**：尚无可用向量。
- **需重新准备**：已有向量与当前所需配置不匹配。
- **未确认**：状态无法确认，不能视为准备完成。

向量准备支持同库增量复用，但不只是“模型名字相同”就一定复用：文本内容和完整向量配置也须匹配。只新增一篇文件时，可复用旧文档的匹配对象；不同库不共享，换向量模型或配置可能需要重新准备。以发送预览为准，不承诺零调用。

### 5.3 使用增强搜索与费用边界

目标版本准备好后，在「搜索」选择「AI 增强搜索」，输入问题并提交。

一次正常增强检索依次做搜索词优化、问题向量、候选重排，最多三个角色请求；首错停止、模型请求不自动重试，也不会暗中改用 BM25。看结果中的实际调用记录，而不是按点击次数猜费用。

**会离开本机的数据：** 构建向量时的新文本片段；增强搜索时的问题、改写问题以及有界候选片段。用网页／云端 AI 客户端检索时，返回的证据摘录也会交给该客户端。不是“原始文件保存在本机，所以任何内容都不出网”。

服务商返回的用量不等于最终账单；到相应服务商控制台核对费用。关闭增强后，本地 BM25 仍可用。

## 六、连接本机 Codex／MCP 客户端

下面以已经安装好的本机 Codex 为例。网页 ChatGPT 不读这份本机配置，请走下一节。

1. 在**准备连接的那个 FolioHook 实例**打开「连接 AI 应用」。
2. 找到「本机 MCP · 八个只读工具」。
3. 先点「运行本地离线 STDIO 自检」。成功应显示八个工具通过；无需 OpenAI Key，也不调用阿里云模型。
4. **默认使用 Codex 界面添加：**「设置 → 插件 → MCP → 添加 → 添加 MCP 服务器」，类型选择 **STDIO**。先核对是否已有同名连接，不覆盖或重复添加。
5. 在 FolioHook 点「复制 TOML（不写配置）」作为填表参考，按[亲手操作教程第 8.2 节](亲手操作教程.md#82-亲手添加连接默认用-codex-设置界面)逐项填写名称、启动命令和两个参数；环境变量及环境变量传递留空，无需 Key。CLI 命令、手改配置文件仅为备选，界面添加成功就不要再执行。
6. 配置完成后，在客户端启用对应连接，必要时重新加载或新开任务。需完整重启客户端时先保存工作。
7. 让 AI 真正列库并检索，确认它调用的是这个连接，而非旧项目、其他同名插件或聊天记录。

不要照抄其他电脑的绝对路径，也不要把隔离测试实例的连接当正式库连接。复制按钮变灰时应先修复启动入口，而不是手工拼一个猜测的命令。

可复制的首次提问：

> 请仅使用我刚配置的 FolioHook MCP，实际调用 retrieval_status 列出可用文献库的名称、简介和 ID。不要读取本地文件或旧聊天代替调用；如果工具不可用，请直接告诉我。

选定库后的提问（替换尖括号内容）：

> 请使用 FolioHook 的「<库名>」。先列出该库版本，明确选择当前激活版本，再调用 search_documents，mode="bm25"，查询「<原文关键词>」。回答时给文件名、PDF 页码或 Markdown 行号；没找到就说没找到，不调用增强模型。

**成功标志：** 实际工具记录能看到库／版本选择和搜索结果，来源与你的测试文件一致。应用内自检通过、配置复制成功、AI 声称“已连接”，都不能单独证明这一点。

MCP 提供八个只读工具，不能通过它删除文档、导入、激活版本或改 Key。增强检索虽然不改资料库，但可以向服务商发送文本并产生费用。

## 七、连接 ChatGPT 网页

这是独立的可选步骤。本节描述本项目已测试的私有开发者连接，不代表已经上架公开插件市场。

### 7.1 先准备权限和官方客户端

先核对你正在使用的 ChatGPT 账户／工作区与 Platform 组织。Tunnel 的创建权限、运行权限和 ChatGPT 开发者模式是不同事项；创建／编辑需要 Tunnels **Read + Manage**，运行／选用需要 **Read + Use**，组织／工作区关联也要匹配。不要猜选只有 ID、无法确认身份的工作区。[官方 Tunnel 说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

按该官方页面中的 Platform Tunnel 设置入口创建本项目专用 Tunnel，记录 Tunnel ID。已有正确资产可以使用，不必每次新建。

FolioHook 当前**不会自动安装**官方 `tunnel-client`，但会优先识别本实例应用根的 `bin/tunnel-client`，其次识别 Homebrew 标准位置（`/opt/homebrew/bin/tunnel-client`、`/usr/local/bin/tunnel-client`）。在「连接 AI 应用」查看「连接程序」：已找到就不重装；未找到请按[亲手操作教程第 9.2 节](亲手操作教程.md#92-安装连接程序mac只需装一次)安装 Homebrew，再执行 `brew install openai/tools/tunnel-client`，确认 `tunnel-client --version` 成功后刷新应用。不要复制别人的运行配置或 Secret Key，也不要关闭系统保护来运行被拦截的文件。[官方安装说明](https://github.com/openai/tunnel-client#install-with-homebrew)

后续桌面包可考虑内置程序，但需要核对客户端及附带组件许可、保留声明、完成签名/公证和干净系统验证；当前不代表已经提供安装包。程序可以随包准备，用户的 Secret Key 和账号授权不能随包共享。

### 7.2 保存运行 Key 与启动

1. 在 OpenAI Platform 为该用途准备专用 **OpenAI API Secret Key**（用于运行 Tunnel 的 API 密钥）；核对目标组织、必要权限及有效期，最终生成与复制由你完成。
2. 回到 FolioHook「连接 AI 应用」→「ChatGPT Secure MCP Tunnel · 真实连接」。不是下方的「离线模拟」。
3. 将完整 **Secret Key** 填入「OpenAI Tunnel 运行 Key」，点「保存运行 Key 到本机钥匙串」。看到已配置即可，不需要展示 Secret Key。
4. 填入本项目 Tunnel ID。ID 是连接身份，不是 API Key。
5. 理解并决定是否接受「官方 Tunnel 客户端断线退避重连；应用不自动重启进程」，接受后勾选。
6. 点「保存连接设置」，再点「启动真实 Tunnel」。

**启动后的自动检查已实现：** 约每两秒检查，最多约 45 秒，达到就绪后停止自动检查。页面会显示本地连接状态，手动「检查真实连接」仍保留。它不是全天持续监控，也不自动重启已经退出的进程。

「未就绪」不一定等于进程已退出；先看状态。不要连续点击启动或重新创建 Tunnel。官方客户端退避重连是传输行为，与增强模型的“零自动重试”不是同一件事。

### 7.3 在 ChatGPT 创建连接

1. 在 ChatGPT 设置中找到「安全与登录」的开发者模式；是否可用取决于账户与工作区政策。
2. 进入插件／应用管理的新增入口，填本项目名称和用途。
3. 连接方式选「隧道」，选择对应 Tunnel。列表没有本次 Tunnel 或只有旧项目时，点「改用隧道 ID」，粘贴与 FolioHook 中一致的完整 `tunnel_…`；不是填 Secret Key。无需因此重建 Tunnel。手填仍失败再核对账户、工作区关联和 Read + Use 权限，不猜测一定是缓存。[官方说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)
4. 本项目当前 MCP 没有实现 OAuth，身份验证选**「无身份验证」**。不要选 OAuth 再填无关 Client ID。
5. 阅读权限与信任提示，确认后创建。
6. 打开创建后的连接，确认发现八个工具。[官方 ChatGPT 连接步骤](https://developers.openai.com/plugins/deploy/connect-chatgpt)

这里的“无身份验证”是本项目 MCP 层的选择，不代表 Tunnel 变成公开无保护服务。手工填写 ID 也不会绕过组织或工作区权限。

如果列表看不到 Tunnel，先核对账户、关联和 Read + Use 权限；不要把这次个人账户测试的特殊设置当作所有账户的通用规则。

### 7.4 从网页完成一次普通检索

在新聊天中选用刚创建的 FolioHook 连接，先用上一节的「列库」提示词，再用 BM25 提示词。

**成功须分三层看：**

1. FolioHook 显示本地 Tunnel 就绪。
2. ChatGPT 创建连接成功，并发现八个工具。
3. 新聊天实际调用工具，返回正确库／版本的证据。

只到第一层不算网页已经可用。电脑及本机服务需要持续运行；关机、休眠或断网后不能假定网页仍能检索。

### 7.5 从网页测试增强搜索

先在 FolioHook 完成第五节；没有目标版本向量时不要反复发增强请求。以下提示会使用真实付费模型，确认后再发送：

> 仅使用这次选中的 FolioHook 连接。请先调用 retrieval_status，选择「<库名>」的当前激活版本，再调用一次 search_documents，mode="enhanced"，问题是「<测试问题>」。不要自动重试，不要回退 BM25。请给答案、文件名和页码／行号，并说明工具响应中实际出现的模型调用审计；看不到的字段不要猜。

展开工具调用检查 `mode="enhanced"`、库／版本、结果与角色审计。一次正常成功链应看到三个角色成功；只看到最终文字答案，不能证明增强链真正执行。

## 八、移除文档与删除文献库

### 8.1 只从今后使用的版本移除几篇

1. 选对库和浏览版本。
2. 单篇：右键文档→「从新版本中移除」。多篇：点「批量管理」，勾选目标，再点「从新版本中移除」。
3. 核对确认框中的文档名单与基础版本，点「确认创建新版本」。
4. 浏览新版本检查无误，再到「版本历史」点「设为当前版本」。

这不会修改旧版本，不删除外部原始文件，也不会立即释放旧版本仍引用的空间。每个版本至少保留一篇文档，不能用此操作移除全部／最后一篇。

**注意：** 旧版本仍可被 MCP 明确指定读取；“当前版本不含该文档”不等于已彻底擦除该文档。

### 8.2 永久删除整个库

只在确定连历史资料与向量都不要时操作：

1. 进入目标「库设置」或管理库入口。
2. 点「永久删除文献库」。
3. 在第二次确认中核对库名、库 ID、历史版本及删除范围，输入准确库名。
4. 确认无误后点「永久删除」。这是不可恢复删除，不是移到废纸篓。

删除包含该库管理的文档副本、派生文本、数据库／索引、全部历史版本、对象和向量。不删除导入前放在其他目录的原始文件，不影响其他库，也不清除应用级共享模型 Key 或连接配置。

不要为了测试按钮而删除正式库；需要练习时另建合成测试库。

## 九、日常启停、资料位置与备份

### 每天怎么开、怎么关

| 用法 | 开始 | 结束 |
|---|---|---|
| 应用内管理／搜索 | 启动项目管理页 | 启动终端按 `Ctrl+C` |
| 本机 MCP | 在客户端启用正确连接，客户端按需启动 stdio | 在客户端禁用／移除该连接；不靠关闭管理页停它 |
| ChatGPT 网页 | 管理页可用，启动真实 Tunnel，检查状态，再在网页选连接 | 先点「停止真实 Tunnel」并确认停止，再停管理服务 |

关闭浏览器标签页不等于停止后台进程。关闭管理服务会停止它拥有的 Tunnel，但本机 stdio 由客户端独立管理。客户端禁用后，已建立会话可能尚未断开；需要确认停止访问时，保存工作并按客户端要求重载／重启，再实际核验，不能只看开关。

### 数据在哪里

默认 macOS 资料根是当前用户的 `~/Library/Application Support/literature-evidence-mcp/`；源码目录内的 `.venv/` 是运行环境，不是文献库。隔离测试实例使用第二节所述的项目内目录。

文献副本、版本和向量在应用资料根；Key 在 macOS 钥匙串。Git 保存源码，**把代码 push 到 GitHub 不等于备份了资料库，也不应把资料与 Key 推上去**。

需要备份时，先停止导入／构建、Tunnel、管理服务和相关 MCP 客户端，再核对实际应用根，备份其完整一致副本与必要原始文件到可信位置。不要只备份某个版本目录或 SQLite 文件，因为版本可能引用共享对象。当前没有经过完整验收的一键备份／跨机恢复向导；新机还须重新配置凭据与连接，不要把普通文件复制当作钥匙串迁移。

## 十、常见问题

| 现象 | 先检查什么 | 不要做什么 |
|---|---|---|
| 管理页打不开 | 启动终端是否仍运行，地址／端口是否与实际输出一致 | 不要猜测并结束其他项目的进程 |
| 端口已占用 | 是否已经开过同一实例；让维护者辨认服务或换空闲端口 | 不要把“占用”当作数据库损坏 |
| 导入后 AI 仍看到旧内容 | 新版本是否成功，是否「设为当前版本」，AI 是否选了正确 ID | 不要重复导入许多次试运气 |
| PDF 没有可用文字 | 是否为扫描图像、加密或提取失败；先用带文本层文件验证 | 不要假定程序自动做 OCR |
| 普通搜索无结果 | 正确库／浏览版本，原文关键词，中文匹配限制 | 不要把空结果当作证据不存在的证明 |
| 文档已向量化但增强不可用 | 目标版本完整向量状态、当前模型配置、增强开关 | 不要只看文档徽标 |
| 模型鉴权／地域／型号错误 | 专用 Key 权限、百炼北京地域、该型号是否仍受支持 | 不要把 Key 发进聊天，或无休止重试 |
| 本地自检通过，客户端没有工具 | 是否真正配置并启用本实例，是否需要重载客户端 | 不要把复制 CLI 当成配置完成 |
| 获取 OAuth 配置出错／does not implement OAuth | 当前项目连接应选「无身份验证」 | 不要随意生成 OAuth 凭据 |
| ChatGPT 创建连接时泛化报错 | 本地真实 Tunnel 当前状态、Key 权限／有效期、Tunnel ID、组织／工作区，以及八工具发现是否成功 | 不要仅凭一句错误断言是某一方故障或反复新建资产 |
| Tunnel 启动后仍未就绪 | 约 45 秒自动检查是否已结束；可点「检查真实连接」并看实际错误 | 不要误以为应用会永久轮询或自动重启 |
| 网页回答正确却不知道是否通过 | 展开实际工具调用，核对目标库／版本、模式、出处和增强审计 | 不要用旧聊天／本地报告中的答案代替实测 |

向维护者求助时，提供：应用版本、默认还是测试实例、操作步骤、错误原文、发生时间、预期与实际结果。截图先遮挡 Key、个人账户与私人文献；不要提供原始凭据文件或整段含秘密日志。

## 十一、照着完成一次验收

验收就是“用一份你知道答案的小资料，看每一步是否真的达到预期”。不需要先学编程，也不需要一开始就装虚拟机。

### 11.1 不花模型费用的练习

在文本编辑器中新建 UTF-8 文件 `练习资料.md`，保存下列**纯合成**内容：

```markdown
# 蓝桥测试记录

标记：bluebridge317。合成储能容量为 31 kWh，调度延迟为 7 秒。
本记录仅用于软件练习，不是真实实验数据。
```

然后逐项检查：

- [ ] 在独立测试实例新建「使用练习」库，从应用文件选择器导入此文件。
- [ ] 浏览版本能看到该文件；普通搜索 `bluebridge317` 返回 31 kWh 和 7 秒。
- [ ] 打开外部原始 Markdown，核对摘录与行号。
- [ ] 再导入第二份不同的合成文件，选“基于当前浏览版本继续”，检查新版本包含两篇，旧版本仍只有一篇。
- [ ] 确认新版本后设为当前版本；本机 MCP 实际列库、列版本、普通查询正确。
- [ ] 若已配网页连接，在 ChatGPT 新聊天选中连接，实际普通查询正确，并可看到工具记录。

### 11.2 可选的付费练习

- [ ] 预览选定版本的向量发送量；确认后只构建一次，核对成功结果。
- [ ] 做一次增强查询，核对答案、出处与实际角色调用记录。
- [ ] 新增文档后再次预览，查看旧对象复用和新增发送量；只预览就能检查计划，不必为了演示再次付费构建。

### 11.3 本轮已经证明什么，还差什么

已在一台 Mac 的独立实例、合成资料上观察到：本机 MCP 实际调用，网页八工具发现与普通搜索，真实向量构建，以及网页增强搜索三个角色的成功审计。启动自动检查和近期搜索交互也有专项验证。

尚不能据此宣布：全新用户导入与原文件定位带练完成、全新 Mac／Windows 安装通过、真实断网恢复通过、大型私人资料库的检索质量已证明，或已经具备正式安装包。

**建议的下一步：** 先按 11.1 由你亲手导入一份练习资料并核对原文，修正文档中卡住的步骤；当前源码整合通过复验后，再由维护者确认 Git 基点并另行安排打包与干净环境安装测试。阅读这份指南不代表已打包、已发布或已推送。
