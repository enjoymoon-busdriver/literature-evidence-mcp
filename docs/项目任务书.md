# FolioHook · 寻章项目任务书

## 目标与技术依据

让个人用户通过清楚的界面管理自己的文献资料库和版本，并让 AI 经 MCP 读取可追溯证据。核心体验是选资料、建库、生成快照、查找内容并回到来源位置。

现有能力和技术合同分别以 [README](../README.md) 与 [ARCHITECTURE](../ARCHITECTURE.md) 为依据。本文负责目标、工作边界与验收安排，不重复底层接口和历史阶段细节。

Mac 和 Windows 应用是产品目标。Windows x64 未签名测试安装包现已获准实施：复用 Python 后端与已有页面，采用 Electron / Forge 外壳和 PyInstaller 目录式运行时。当前进度与证据仍以本机活看板为准；实现、云端构建、Windows 11 干净客户端验收和正式发布是不同阶段，不能互相替代。Mac 打包、签名购买、公证和正式发布不在本次范围。

## 当前工作范围

正式界面及后续增补已经开发工作树实现、独立工作树验收，并在本轮纳入主工作区。精确版本、未提交状态、负责人、复验与推送结果由 [唯一执行看板](执行看板.md) 记录；源码整合不等于已打包或已发布。

源码与教程整合、离线复验及原主分支推送已完成。本轮允许在独立分支做必要 Windows 兼容改动、安装构建依赖、提交/push、运行标准 Windows GitHub Actions 并在零新增费用边界内保存测试安装包；不合并主分支、不创建正式 Release。测试仅用合成资料，不重建已清理的测试凭据/连接，不修改客户端共享配置，不再次调用真实模型或复用旧工程凭据。

用户之前补充的“向 AI 展示资料库名称、简介和快照”属于应用 `retrieval_status` 功能，与客户端全局连接配置是两件事。该功能应在真实工具调用中核验，不能用它解释共享配置的未知差异。

## 执行顺序与完成条件

| 工作 | 完成条件 |
|---|---|
| 治理与交接 | 一个仓库启动入口、一个任务书、一个主工作区活看板；开发与验收任务收到同一个入口及各自范围 |
| 本机 MCP | 在已批准的独立实例和连接上由真实客户端发现八工具，完成列库、列快照、核验、BM25 检索和证据读取；核对库名与简介，记录实际结果 |
| 网页 Tunnel | 在相应授权和用户凭据/权限就绪后验证网页连接；本地健康不代替网页发现和调用工具 |
| 三模型增强 | 在相应授权和用户凭据就绪后验证问题改写、向量召回与重排的真实调用，记录实际发送范围与结果 |
| 用户亲手带练 | 用户在已验收实例实际完成关键界面与连接操作；导入未完成、待输入 Key 或待登录均如实保留，不由后台替代操作冒充通过 |
| 开发成果整合 | 管理任务根据代码交接与各层验收证据整理待整合变更；提交、推送及发布按用户授权执行 |

每项工作采用下列四个独立状态，不用一个“已完成”覆盖全部含义：

- **实现完成**：目标代码与界面已具备，注明所属版本与工作树。
- **离线通过**：自动测试、假服务或合成协议流程通过，注明覆盖范围。
- **真实链路通过**：指定真实客户端、模型或 Tunnel 实际调用成功，分别记录，不互相代替。
- **用户带练完成**：用户亲手完成对应操作，必要输入与权限已实际处理。

历史版本曾有的真实链路记录只能证明当时对象；当前正式界面和新实例必须按本轮证据判断。当前实时进度、异常和继续条件全部放在执行看板，不在本任务书重复维护。
